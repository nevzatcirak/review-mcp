**R-1 binds harder here,** because the code is on the user's own machine:
- review-mcp reads the repository with git, read-only.
- It never builds, runs or loads the code.
- It never runs a hook, a filter, a textconv or diff driver, or an fsmonitor.
- It never writes to the repository, its index, its config or its refs.
- It never touches the network for this work.

## Why

Owner request: review work before it is pushed, from the MCP client and from a git hook. Today every review reads a pull request through a provider's API, so work that exists only locally cannot be reviewed until it is pushed and a pull request is opened.

## 0. Decisions

1. **A tool, `local_review`** (owner). It reviews the difference between a base commit and the local work of a repository on the machine where review-mcp runs. The result is shown to the client only: nothing is published, and nothing is sent anywhere except the configured LLM endpoint.
2. **What is reviewed** (owner):
   - the commits after the merge base of `base` and `HEAD`;
   - plus, by default, the uncommitted changes to tracked files, staged and unstaged (`include_uncommitted`, default true);
   - plus, only on request, untracked files that `.gitignore` does not exclude (`include_untracked`, default false). An untracked `.env` that is not ignored must not reach the model by surprise.
3. **A CLI command for hooks** (owner): `review-mcp local review`, with CI mode's exit codes and `--fail-on`, so that a `pre-push` hook can run it.
4. **Stdio and CLI only** (architect). In serve mode the tool is not registered, and the prompt refuses `repo_path`: the server's disk is not the user's.
5. **Base resolution is local and stated** (architect). No fetch. The default base is tried in this order:
   1. the current branch's upstream;
   2. `origin/HEAD`;
   3. `origin/main`, `origin/master`;
   4. `main`, `master`.

   The result names the base ref and commit. When the base is a remote-tracking ref, a note says it is the local copy and may be behind the remote.
6. **Same pipeline, a read-only source** (architect). The local repository is presented to the pipeline as a provider of kind `local` that implements the read methods. Every write method returns `unsupported` before doing anything. So prompts, budget, splitting, focus, focus profiles, repository config, the docs focus and the result shape are the ones of `pr_review`.
7. **Off for what does not apply** (architect):
   - `publish` and `findings`, `incremental`, `related`, the decision tool and issue lookups do not exist for local reviews;
   - `issue_context` is accepted;
   - `pr_ask`, `pr_describe` and `pr_improve` on local work are backlog.
8. **Allowed roots** (architect). `local.allowed_roots` (operator, default empty = any git work tree) limits `repo_path` to directories under the listed roots, after symlinks are resolved. `local.enabled` (default true) removes the tool when false.

## 1. WP-24a — the local source (Opus)

Commits:
1. `feat(gitctx): safe local repository reads`
2. `feat(provider): local work as a read-only source`

### 1.0 Entry criteria (closed in the WP-24a report before production code)

- **E1:** every git invocation that review-mcp already makes on its cache (`gitctx`), with the options and environment it sets. State which of them stop hooks, fsmonitor, textconv, external diff, lazy fetch and protocol access, and what must be added for a repository the user owns.
- **E2:** how a repository owned by another OS user behaves (`safe.directory`), and the error the user should see. review-mcp never adds a `safe.directory` entry.
- **E3:** whether `gitctx` can search and read the user's repository at a commit without writing to it (the X-45 read view with `GIT_OBJECT_DIRECTORY`), and if not, the smallest copy that keeps the user's repository untouched (for example `git clone --local --no-checkout` into the cache).
- **E4:** where the pipeline resolves the provider (`Deps.Resolver`, `Resolve(url)`), and the least intrusive way to give it a `local` source that no URL-taking tool can reach.
- **E5:** worktrees, submodules (listed, not entered), a detached HEAD, a shallow clone (no merge base), Windows paths and line endings.

### 1.1 Safe git

Amended 2026-11-15 after the WP-24a report (E1, DQ-1 to DQ-3, DQ-6), because the options below alone do not stop clean filters, and `git diff` rewrites the index it reads.

Every git call on the user's repository is built in one place.

**Options:**
- `-c core.hooksPath=<an empty directory under review-mcp's temp>`
- `-c core.fsmonitor=false`
- `-c diff.external=`
- `-c protocol.allow=never`
- `--no-optional-locks`

**Environment** (an allow-list, never the parent's environment):
- `PATH` (and `SYSTEMROOT` on Windows)
- `HOME`/`XDG_CONFIG_HOME`/`USERPROFILE` pointing at an empty directory
- `GIT_CONFIG_NOSYSTEM=1`
- `GIT_TERMINAL_PROMPT=0`
- `GIT_NO_LAZY_FETCH=1`
- `GIT_OPTIONAL_LOCKS=0`
- `LC_ALL=C`

So neither the global nor the system configuration is read.

**Two places a command runs:**
- **In the repository:** `rev-parse`, `symbolic-ref`, `for-each-ref`, `merge-base`, `log`, `ls-files`, and a diff of two commits. None of these reads a work-tree file's content.
- **Through a read view:** a bare repository written by review-mcp in its temporary directory, with no configuration but its format, and `GIT_OBJECT_DIRECTORY` set to the repository's own objects. It runs:
  - blob and tree reads (`cat-file`, `ls-tree`);
  - the diff against the work tree, with `--work-tree` and a **private copy of the index** (`GIT_INDEX_FILE`).

  The view defines no filter, textconv or diff driver, so the work tree's `.gitattributes` cannot name one that runs, and the user's index is never written.

Diffs add `--no-ext-diff --no-textconv --no-color -M`.

**Commands:** No command that writes to the user's repository is ever run. A test checks every call site against a fixed allow-list:
- `rev-parse`, `merge-base`, `diff`, `ls-files`, `ls-tree`, `cat-file`, `log`, `for-each-ref`, `symbolic-ref`, `grep`;
- `rev-list` (for the search in WP-24b);
- one restricted form of `config` (below).

`show` is not needed.

**Untracked files** (with `include_untracked`) are listed with:
- the repository's ignore rules (`.gitignore`, `.git/info/exclude`, the repository config's `core.excludesFile`);
- **and the user's global ignore rules.** The global excludes file is found with `git config --global --get --path core.excludesFile`, run with the real `HOME` and no repository. That is the only `config` form allowed: `--get` of that one key, nothing else. When the key is unset, the default `$XDG_CONFIG_HOME/git/ignore` (or `~/.config/git/ignore`) is used. The file is passed as `-c core.excludesFile=<path>` to `ls-files`. Reason: users keep secret files out of git with global rules too, and opting in to untracked files must not send them to the model.
- **Likely secrets always stay out**, even when not ignored: `.env`, `.env.*`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.jks`, `*.keystore`, `id_rsa*`, `id_ed25519*`, `.netrc`, `.npmrc`, `.pypirc`, `*.tfvars`, and `credentials*`. These are compared on the base name, case-insensitively. They are counted in the result (`local.untracked_held_back`) with the note "N untracked files were left out because their names suggest secrets." This applies to untracked files only. A tracked file is already in git, and its changes are reviewed like any other.

### 1.2 Repository and base

- `repo_path`:
  - an absolute path;
  - symlinks resolved;
  - `rev-parse --show-toplevel` gives the work tree, and a subdirectory is accepted and means its top level;
  - a bare repository is refused;
  - outside `local.allowed_roots`, when that is set, it is refused before any git call.
- `base`:
  - a ref or a commit, validated as a ref name or a hexadecimal commit;
  - without it, the order in §0 item 5;
  - none found: `ErrLocalNoBase`, whose message names what was tried and how to pass `base`.
- Merge base:
  - `git merge-base <base> HEAD`;
  - none (unrelated histories, or a shallow clone that misses it): refused with a sentence that says so.
- Head:
  - `HEAD`, with an unborn branch refused;
  - with `include_uncommitted`, the head side is the work tree for tracked files.

### 1.3 The `local` source

It implements `provider.Provider` for one repository and one base:
- `GetPullRequest`:
  - the title is the newest commit's subject after the merge base, or "Uncommitted changes" when there is none;
  - the description lists at most 20 commit subjects, newest first;
  - the head is `HEAD`'s commit; the base is the merge base;
  - no author or URL.
- `GetCommitMessages`: subjects and bodies after the merge base, oldest first, capped as the providers do.
- `GetDiff`:
  - the merge base against `HEAD`, or against the work tree with `include_uncommitted`;
  - plus untracked files as added files with `include_untracked` (`ls-files --others --exclude-standard`);
  - the same file, size and binary limits and content statuses as the providers;
  - a file whose content cannot be read gets its status, never an error for the whole review.
- `GetFileAt`: `git show <rev>:<path>` with the same size cap. For the head side with `include_uncommitted`, the work-tree file, read with no symlink following outside the work tree.
- `ListDir`: `ls-tree` at a revision.
- `FileLineURL`: empty; the markdown shows `path:line`.
- `Capabilities`: everything off except reads.
- Every write method returns `ClassUnsupported` with no git call. The contract suite gains a `local` run that checks this.
- **Empty:** nothing to review returns the existing empty result with no model call, and with a note that names the base and what was included.

### 1.4 Canaries (WP-24a)

- (a) A repository with `core.fsmonitor` set to a script that writes a marker file: no marker after a local review. Mutation: drop `-c core.fsmonitor=false`.
- (b) A repository with a `.gitattributes` diff driver whose textconv writes a marker: no marker. Mutation: drop `--no-textconv`.
- (c) A `pre-commit`/`post-checkout` hook writing a marker never runs (no write command is run either). Mutation: run `checkout` in a test helper path; the allow-list test must fail.
- (d) The index file's mtime and content are unchanged after a review with uncommitted changes. Mutation: diff against the repository's own index instead of the private copy (optional locks never protected the index).
- (e) `include_untracked=false` leaves an untracked, non-ignored file out; `true` includes it; an ignored file never appears. Mutation: default untracked to true.
- (f) A path outside `allowed_roots` (including through a symlink) is refused before any git call. Mutation: check the path before resolving symlinks.
- (g) Every write method returns `unsupported` with no git call. Mutation: implement `PostComment` as a no-op success.
- (g2) An untracked file ignored only by the user's global excludes file is left out with `include_untracked`. Mutation: skip the global excludes file.
- (g3) An untracked, not ignored `.env` and `deploy.pem` are left out and counted. Mutation: an empty secret list.

## 2. WP-24b — tool, prompt, context (Opus)

### 2.1 `local_review` (stdio only)

Input:
- `repo_path` (required);
- `base`;
- `include_uncommitted` (default true);
- `include_untracked` (default false);
- `focus`;
- `extra_instructions`;
- `output_language`;
- `max_findings`;
- `issue_context`;
- `wait_seconds`, with the job machinery as for `pr_review`.

Output: the `pr_review` structured result, with:
- `pr.kind: "local"`;
- `pr.url: null`;
- a `local` object: `repo_path` (the work tree's absolute path), `base_ref`, `base_sha`, `merge_base`, `head_sha`, `uncommitted` (bool), `untracked_files` (int), `untracked_held_back` (int);
- declared in the output schema.

Description: "Reviews local work before it is pushed: the commits after the merge base with base (default: the branch's upstream), plus uncommitted changes to tracked files; untracked files only with include_untracked. Read-only: nothing is published and the repository is not changed. Use it before pushing; use pr_review once a pull request exists."

Annotations: read-only, not destructive, idempotent, not open-world. It is registered only when `local.enabled` is true and the mode is stdio. Instructions get one sentence when it is registered.

### 2.2 Prompt

`multi_perspective_review` gains `repo_path` and `base`; exactly one of `pr_url` and `repo_path` must be given. With `repo_path`:
- the message tells the client to call `local_review` once per focus, then to show the merged findings (publishing does not exist);
- the default list and the focus rules use the local diff's files;
- the repository config is read at the merge base;
- in serve mode, `repo_path` is `InvalidParams` ("local reviews run in stdio mode only").

### 2.3 Repository config and context

- `.review-mcp.toml`, the style file and focus profiles are read at the **merge base**, by the same rule as the base revision of a pull request.
- Repository context, when `context.repo.enabled`:
  - uses the user's repository read-only at `HEAD` (E3), not a clone of a remote;
  - uses in uncommitted changes are not searched, and a note says so when `include_uncommitted` added files;
  - WP-22's rule (uses in changed files outside the diff) applies with the local hunks.
- The repository tools (X-43) run on the same read-only view. Their `paths` confinement is unchanged.

### 2.4 Tests and canaries (WP-24b)

- Schema tests for the `local` object and every nullable field.
- (h) In serve mode the tool is absent and the prompt refuses `repo_path`. Mutation: register it in serve.
- (i) The repository config is read at the merge base, not at `HEAD` or the work tree (the fixture edits `.review-mcp.toml` in an uncommitted change). Mutation: read the work tree.
- (j) `publish`/`findings`/`incremental`/`related` are not in the input schema. Mutation: accept `publish` and route it to a write (the write must fail with `unsupported` and the test must catch the schema).
- (k) Leak test: no file content, no absolute path beyond the work tree's base name, and no token in logs at debug level.

### 3.1 CLI

```
review-mcp local review [--path DIR] [--base REF] [--uncommitted=true|false] [--untracked]
                        [--focus NAME] [--max-findings N] [--output-language L]
                        [--issue-context-file PATH] [--json] [--timeout D]
                        [--fail-on security|any|issue-not-compliant]
```

- `--path` defaults to the current directory.
- Exit codes are the same as CI mode's:
  - 0 done;
  - 1 the run failed;
  - 2 usage error or no repository/base;
  - 3 a `--fail-on` condition is met.
- Markdown goes to standard output, errors to standard error. Settings come only from `REVIEW_MCP_*` and the config file, as for the tools.
- The command never asks a question on the terminal.

### 3.2 Docs

- `docs/local-review.md` (new), covering:
  - what is reviewed, the defaults and the base order;
  - the stale remote-tracking note;
  - the read-only guarantees, listing what review-mcp never runs;
  - what goes to the LLM endpoint;
  - untracked files and secrets;
  - `allowed_roots`;
  - the CLI and its exit codes;
  - a `pre-push` hook sample for POSIX shells and one for Windows (Git for Windows runs hooks with its bundled shell);
  - how to skip it once (`git push --no-verify`);
  - the time a review adds;
  - what is not available.
- README (one row and a link), `docs/setup.md` (the settings), `docs/serve.md` (not in serve), X-52 in `docs/design/v1-design-decisions.md`, and CHANGELOG `[Unreleased]` (planned `2.10.0-rc.1`).

## 4. Acceptance (architect's container with a recording test endpoint; owner on a work machine optional)

| # | Case | Expected |
|---|---|---|
| Q1 | Two unpushed commits, clean work tree, upstream set | The diff is exactly those commits; `base_ref` is the upstream. |
| Q2 | Plus an unstaged and a staged edit | Both are in the diff; `uncommitted: true`. With `include_uncommitted=false`, they are not. |
| Q3 | An untracked file plus an ignored file | Absent by default; with `include_untracked`, only the non-ignored one is present. |

| Q5 | fsmonitor, textconv and hook traps in the repository | No marker file. The index is unchanged. |

| Q8 | `review-mcp local review --fail-on any` in a `pre-push` hook | Exit 3 blocks the push; `--no-verify` skips it. |
| Q9 | The prompt with `repo_path` | It lists the focuses from the local files; in serve mode it refuses `repo_path`. |
| Q10 | Nothing to review | The empty result, no model call. |
| Q11 | Windows (owner, optional) | A local review of a real work tree; the line endings do not mark every line as changed. |
