R-1 is unchanged.

## Why (generic record of a live diagnostic, 2026-11-04/05)

A stdio review of a 42-file Java pull request in two modules: diff about 94k tokens in one model call; repository context `used` with 20 symbols (the cap), **8 uses in 7 files**, block 1,373 of 2,000 tokens. About half of the 20 symbols were bean accessors of the same fields (`getX`/`setX`) and a logger constant. Raising `max_hits_per_symbol` cannot help: most symbols had no use outside the pull request's own files, because in a large change the callers are mostly in the change itself, and those files are excluded from the search, while the reviewer sees only their hunks. A second run on a newer binary gave the same numbers. The first run also showed that `npx -y <package>` without a version ran a binary older than 2.4 (an unknown-key warning for a 2.4 key), so repository tools were never on.

## 1. Symbol ranking

Commit 1: `fix(gitctx): rank accessors and logger names below other symbols`
- `LOGGER`, `LOG`, `logger`, `log` and `serialVersionUID` join the ubiquitous names that are never searched (`noiseNames`).
- An accessor (`get`, `set` or `is` followed by an upper-case letter) whose remainder, with its first letter lower-cased, names a field defined or changed in the same file (a definition line in the patch, or a field declaration on a changed line) ranks after every other symbol of its rank. A `getX`/`setX`/`isX` group counts once against `max_symbols`; every name of the group is still searched.
- Canary (z): a fixture with 12 accessor pairs and 10 service methods keeps all 10 service methods within a cap of 20. Mutation: no demotion.
- Canary (z2): `LOGGER` is not a symbol. Mutation: remove it from the noise names.

## 2. Uses in changed files outside the diff

Commit 2: `feat(gitctx): uses in changed files outside their hunks`
- `Query` gains `Hunks map[string][]LineRange`: the pull request's files and the head-side line ranges the model sees, that is each hunk widened by `diff.extra_lines_before`/`diff.extra_lines_after` (the same ranges the prompt shows). A changed file is no longer excluded by pathspec; a hit in it is kept when its line lies outside every range, and dropped when inside one. A deleted file has no head side and stays excluded.
- Such a hit is labelled in the block: `[path:line] uses Name (in a changed file, outside the diff)`. The block's header sentence already covers changed entries; add "Entries in a changed file outside the diff show code the diff does not show." after its second sentence.
- Within a symbol's hits, hits in unchanged files come first, then hits in changed files, each group with the existing preferences (distinct files, language of the definition).
- Reviews in parts keep today's rule for other parts' files (whole files, marked as reviewed in another part); for the part's own files the new rule applies.
- Coverage: `coverage.repo_context` gains `references_in_changed_files` (int, declared in the output schema; 0 when none). The overview coverage line adds ", N of them in changed files outside the diff" when N > 0.
- Canary (y): a use in an unchanged part of a changed file is a hit with the label. Mutation: keep the pathspec exclusion of changed files.
- Canary (y2): a use inside a widened hunk is not a hit. Mutation: ignore the widening.

## 3. Version drift

Commit 3: `fix(config): name the binary's version in unknown-key warnings`
- The warning becomes: "unknown environment variable %s (ignored; this is review-mcp %s, and the setting may belong to a newer version)". The same for unknown configuration-file keys. `server_info` warnings carry the same text.
- Test: the warning carries the version. Canary (x): drop the version argument.

Commit 4: `docs: pin the package version in client setups`
- README, `docs/setup.md`, `docs/getting-started.md`, `docs/serve.md` and every client snippet use `@nevzatcirak/review-mcp@latest` (or a pinned version) instead of the bare package name, and `docs/troubleshooting.md` gains "An older version runs although a newer one is released": `npx -y` reuses a cached copy when no version is named; check with `npx -y @nevzatcirak/review-mcp@latest version`.
- `docs/repo-context.md`: the new hit rule, the label, `references_in_changed_files`, and a note that raising `max_hits_per_symbol` does not help when the uses are inside the pull request.
- `docs/design/v1-design-decisions.md`: the X-22 amendment. CHANGELOG `[Unreleased]`.
