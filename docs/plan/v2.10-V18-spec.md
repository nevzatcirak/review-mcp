R-1 is unchanged: the trace uses `git grep` and blob reads on the cached head commit, exactly as repository context does. Nothing is built, run, parsed by a compiler or language server, or loaded as code.

## Why

User feedback: reviews find local problems but miss effects that travel through other classes. Repository context today is one hop: it shows up to 5 uses of up to 20 changed symbols, 3 lines each, within 2,000 tokens, so the model sees B calling the changed A but never C calling B, and often not even which method of B the use sits in. The repository tools (V-8) can go further, but only when the model decides to. Literature (see `docs/design/v2.9-review-quality.md`): a substantial share of real review comments needs file- or repository-level context; definition context helps; more retrieved context can also hurt, so the trace is budgeted, ranked and measured (V-9).

## 0. Decisions

1. **A deterministic, name-based, multi-hop trace** (owner). From the changed symbols, follow uses to the definition that encloses each use, then the uses of that definition, up to `depth`. Name matching, not type resolution: the prompt and the docs say so.
2. **Off by default in 2.10** (architect). `context.impact.enabled` (default false) needs `context.repo.enabled`. It becomes a default only if V-9 shows a gain without a loss in precision; that decision is the owner's, after the measurement.
3. **Its own budget** (architect). The trace has `context.impact.max_tokens` (default 4,000), separate from the 2,000 of the existing block, so turning it on does not crowd out what is there.
4. **Scopes** (owner): where to trace (`paths`, `exclude_paths`) and what matters (`entry_points`), settable by the operator, by the repository config, and per call with the `impact_paths` argument of `pr_review`, with X-40 precedence (tool argument > repository file > operator; numbers only tighten).
5. **Widely used names are not expanded** (architect). A node whose uses exceed 3 × `max_callers_per_node` is shown once, marked "widely used, not followed". This bounds the fan-out of names like `save`, `process`, `handle`, and the coverage says how many were not followed.
6. **Findings in callers go to the overview** with a link to the caller's line at the head commit (provider `FileLineURL`), never inline: the caller is not in the diff. This is the existing path for findings that cannot be anchored.
7. **An `impact` focus** (owner): a seventh known focus value for `multi_perspective_review` and `focus`, whose sentence asks only for effects along the chains. It is not added to the default focus list.
8. **Not in serve mode** (architect), because repository context is not (X-22).
9. **Custom named focuses are a separate item** (architect): V-19, specified after V-18. The free-text `focus` (1–200 characters) already lets a user name an area today.

## 1. WP-20a — the trace engine (Opus)

Commits:
1. `feat(gitctx): enclosing definition of a line`
2. `feat(gitctx): multi-hop impact trace`

Symbol ranking (accessors, logger names) and uses in changed files outside their hunks ship earlier, in WP-22 (`docs/plan/v2.8-WP22-repoctx-spec.md`); the trace builds on both.

### 1.1 Enclosing definition (`internal/gitctx`)

`func EnclosingDefinition(content []byte, lang string, line int) (Definition, bool)`
- `Definition{Name string; Line int; Text string}`: the nearest line at or above `line` for which the existing `definitionName(text, lang, section=true)` gives a valid symbol, and whose indentation is smaller than the use's (or equal, for a use on the definition line itself; a use on a class line is the class). Python uses indentation by rule; brace languages use the same indentation heuristic.
- Looks back at most 400 lines; none found → `ok=false` (the use is file level).
- Pure; table tests in Java, Kotlin, C#, TypeScript, Go and Python, with nested classes, lambdas, an anonymous class, a one-line function, a decorator, and a use inside a string or comment (still found: name matching).

### 1.2 The trace (`internal/gitctx`, new file `impact.go`)

```go
type ImpactQuery struct {
	Seeds   []Symbol       // ExtractSymbols, test and new-only symbols removed
	Hunks   map[string][]LineRange // the pull request's own files and their changed line ranges (head side): a hit inside a range is dropped, outside it is kept and marked
	Filter  *filter.Filter // as Query
	Scope   ImpactScope
	Depth              int // 1..3
	MaxCallersPerNode  int // 1..20
	MaxLinks           int // 1..200
}

type ImpactScope struct {
	Paths, ExcludePaths []string // directory prefixes ("" = whole repository)
	EntryPoints         []string // globs (filter syntax)
}

type ImpactNode struct {
	Name     string
	Path     string // file of the enclosing definition ("" for a seed)
	DefLine  int
	DefText  string // untrusted repository text, one line
	UseLine  int    // the line in Path that uses Parent
	UseText  string // untrusted, the use with up to 2 lines around it
	Hop      int    // 0 for a seed
	Parent   int    // index of the parent node, -1 for a seed
	Kind     string // "call" or "inherits" (the use line matches extends/implements/override patterns, or ": Name" in a class header)
	Entry    bool   // Path matches an entry point
	InPR     bool   // Path is a file of the pull request (the use is outside its hunks)
	NotFollowed string // "" | "widely_used" | "depth" | "budget" | "out_of_scope"
}

type ImpactResult struct {
	Nodes []ImpactNode
	Seeds, Links, DepthReached, NotFollowed, EntryPointsReached int
	SkippedBlobs int
	Truncated    bool
}

func Trace(ctx context.Context, c Checkout, q ImpactQuery) (ImpactResult, error)
```

- **Chains pass through the pull request's own files.** A hit in a changed file is kept when its line lies outside that file's hunks (the reviewer sees the hunks already, not the rest of the file); the node is marked `[changed file]` and is followed like any other. A hit inside a hunk is dropped (it is in the diff). Large pull requests (a stacked change of 40+ files is common) carry most of their own callers, so excluding the changed files entirely would cut the chains there.
- Breadth first, seeds in rank order. Hop k+1 searches the names of hop-k nodes with the existing `Grep` machinery (same exclusions, same blob rules, same timeouts and output caps), `MaxHitsPerSymbol = MaxCallersPerNode`, preferring files in the seed's language, then distinct files.
- For each hit: read the blob at head (size-capped, the existing reader), find `EnclosingDefinition`. A hit without one becomes a leaf with the file as its name (`Name` = base name, `NotFollowed = "depth"`).
- Visited set by (path, definition line): a cycle is not followed twice.
- Scope: a hit outside `Paths` or inside `ExcludePaths` is dropped before it is counted (`out_of_scope` count only). Entry points mark nodes; they are still followed.
- Widely used: a name whose search alone returns more than `3 × MaxCallersPerNode` hits (before the cap) keeps its first hits and gets `NotFollowed = "widely_used"`; its children are not searched.
- Stop when `MaxLinks` nodes exist (`budget`), at `Depth` (`depth`), or at the existing total search time (`Truncated`).
- Logs (debug): counts only (seeds, nodes, links, not followed per reason, depth reached, duration). Never a name, path or text.

### 1.3 Canaries (WP-20a)

- (a) A use two hops away is found (Java fixture: `Repo.save` ← `Service.persist` ← `Controller.submit`). Mutation: stop after hop 1.
- (b) The enclosing method, not the class, is the parent of a use inside a method. Mutation: take the first definition above regardless of indentation.
- (c) Cycle: `a` calls `b` calls `a` terminates with each node once. Mutation: drop the visited set (the test has a timeout).
- (d) Widely used: a name with 30 uses and cap 5 is not followed. Mutation: remove the 3× rule.
- (e) `ExcludePaths` drops a hit. Mutation: ignore the scope.
- (f) An `implements` line is `Kind = "inherits"`. Mutation: classify every hit as call.
- (f2) A use in a changed file outside its hunks is a node marked `InPR` and is followed; a use inside a hunk is not a node. Mutation: exclude changed files entirely.

### 2.1 Configuration (operator)

| Key | Env | Default | Bounds |
|---|---|---|---|
| `context.impact.enabled` | `REVIEW_MCP_CONTEXT_IMPACT_ENABLED` | false | needs `context.repo.enabled`; a startup note (not an error) when set without it |
| `context.impact.depth` | `REVIEW_MCP_CONTEXT_IMPACT_DEPTH` | 2 | 1–3 |
| `context.impact.max_callers_per_node` | `REVIEW_MCP_CONTEXT_IMPACT_MAX_CALLERS_PER_NODE` | 5 | 1–20 |
| `context.impact.max_links` | `REVIEW_MCP_CONTEXT_IMPACT_MAX_LINKS` | 40 | 1–200 |
| `context.impact.max_tokens` | `REVIEW_MCP_CONTEXT_IMPACT_MAX_TOKENS` | 4000 | 500–20000 |
| `context.impact.paths` | `REVIEW_MCP_CONTEXT_IMPACT_PATHS` | [] | ≤ 20 prefixes |
| `context.impact.exclude_paths` | `REVIEW_MCP_CONTEXT_IMPACT_EXCLUDE_PATHS` | [] | ≤ 20 prefixes |
| `context.impact.entry_points` | `REVIEW_MCP_CONTEXT_IMPACT_ENTRY_POINTS` | [] | ≤ 20 globs |

Prefixes and globs are repository-relative, validated like `filter` globs and the V-13b `paths` (no `..`, no absolute paths, no leading `/`). `server_info` shows them in `config.values`. Serve mode: the keys are accepted and inert (repository context is off there); `server_info` says so.

### 2.2 Repository config (`.review-mcp.toml`, X-40)

Allow-list additions: `context.impact.enabled` (may turn it **off** only; turning it on needs the operator), `context.impact.depth` and `context.impact.max_callers_per_node` and `context.impact.max_links` (only lower), `context.impact.paths`, `context.impact.exclude_paths`, `context.impact.entry_points` (replace the operator's lists; exclusions add). The repository file is read at the base revision as today, so a pull request cannot change its own scope.

### 2.3 Tool argument

`pr_review` gains `impact_paths` (optional, 1–10 repository-relative prefixes, each ≤ 200 bytes, same validation): for this call it replaces `context.impact.paths` and enables the trace when the operator enabled repository context, even if `context.impact.enabled` is false. It is refused with `findings` (no model call) and ignored with a note when repository context is off. `diag review` gains `--impact=on|off` and `--impact-paths=a,b`.

### 2.4 The prompt block

After the existing repository-context block, fenced as untrusted text under this fixed header:

```text
Impact chains of symbols changed in this pull request (read-only context, found by name matching: a link may be wrong, and calls through reflection, dependency injection, events or dynamic dispatch are missing). For each chain, check whether the change breaks or silently alters what the callers rely on (arguments, return values, null or error cases, units, ordering, side effects). Report a problem in a caller only when this pull request causes it, and name the caller's file and line. Lines marked [entry point] are where users or other systems reach the code.
```

Body, one tree per seed, in rank order:

```text
OrderRepository.save  (signature changed)  src/.../OrderRepository.java:23
  ← OrderService.persist  src/.../OrderService.java:51
      uses at :58: repository.save(order);
    ← CheckoutController.submit  src/.../CheckoutController.java:40  [entry point]
        uses at :43: orderService.persist(cart.toOrder());
  ⋯ 7 more uses of save not followed (widely used)
```

- Hop-1 nodes carry the definition line and the use with 2 lines around it; deeper hops the definition line and the use line only. Every text line is sanitized like the repository-context snippets (control characters, fence-safe, 400-byte line cut).
- Filled in rank order until `max_tokens`; the rest is counted (`budget`).
- The seed line names its rank in words: `removed or renamed`, `signature changed`, `body changed`.

### 2.5 Findings, coverage, notes

- A finding whose path is not in the diff and is a node of the trace is placed in the overview with a link to that line at the head commit (`FileLineURL`); a provider without file-line URLs lists the path and line as text. Inline placement is never attempted for it.
- `coverage.impact` (structured, declared in the output schema): `status` (`on`, `off`, `skipped_no_symbols`, `failed`, `repo_context_off`), `seeds`, `links`, `depth_reached`, `not_followed` {`widely_used`, `depth`, `budget`, `out_of_scope`}, `entry_points_reached`, `scope_source` (`tool`, `repo_config`, `operator`, `none`), `truncated`.
- Overview coverage line: "Impact: 6 symbols traced, 23 links to depth 2 (3 not followed: widely used); found by name matching."
- Notes: `NoteImpactRepoContextOff` when `impact_paths` is given without repository context; `NoteImpactTruncated` when the budget or time cut the trace.
- Reviews in parts: the trace is computed once for the pull request; each part gets the chains whose seeds are defined in that part's files (seeds of other parts are dropped there), within the same budget.
- Incremental runs: seeds come from the reduced diff, as the existing symbols do.
- `pr_ask`: not in V-18 (backlog).

### 2.6 The `impact` focus

`FocusImpact = "impact"`, added to `FocusValues` after `docs`. Sentence: "This review covers the effects of this change on the rest of the code only: callers and implementations that the change breaks or silently alters (arguments, return values, null or error cases, units, ordering, side effects, overridden behaviour), shown in the impact chains and the repository context. Report a problem only when this pull request causes it, and name the affected file and line." With focus `impact` and the trace off, the run proceeds with repository context only and adds `NoteImpactFocusWithoutTrace`. The repository-config `review.focuses` accepts it.

### 2.7 Tests and canaries (WP-20b)

- Output schema validated for: trace on, off, repo context off, truncated, every scope source.
- (g) Repository config cannot turn the trace on. Mutation: allow `true`.
- (h) Repository config can only lower `depth`. Mutation: accept a higher value.
- (i) `impact_paths` replaces the configured paths for that call only. Mutation: merge them.
- (j) A caller finding is overview-only with a head-commit link. Mutation: try inline placement.
- (k) Budget: a trace over `max_tokens` is cut at a tree boundary and counted. Mutation: cut mid-line.
- (l) Leak test: no node name, path or snippet in logs at debug level.
